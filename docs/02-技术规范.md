## 4. 代码风格

- **强制**：每个公开函数都有 `///` 文档注释
- **强制**：函数体不超过 30 行（必要时拆函数）
- **强制**：避免单字母变量（除循环计数器 `i`）
- **推荐**：优先用 `let` 而非 `var`
- **强制**：所有 UI 文案硬编码中文即可（不做国际化）
- **强制**：金额一律用 `Decimal` 类型（避免 Double 精度问题）
- **强制**：UI 状态用 `@State` 私有属性

## 5. 关键技术决策

### 5.1 为什么用 Decimal 而不是 Double？
财务场景严禁浮点误差。`Double` 在 `0.1 + 0.2` 时会出现 `0.30000000000000004`，而 `Decimal` 是定点数，零误差。

### 5.2 为什么用纯函数做转换？
- **易测试**：无依赖，输入输出明确
- **可复用**：未来若加 WatchOS、macOS 版本直接搬
- **可独立开发**：不用等 UI 也能写完核心逻辑
- **可单元测试覆盖率容易达标**

### 5.3 为什么零第三方依赖？
- **学习友好**：少一层黑盒
- **可靠性**：不担心依赖过期、作者弃坑
- **包体小**：App 安装包 < 5MB

## 7. 提交流程

- **类型**：`docs` / `chore` / `feat` / `test` / `ui` / `fix` / `refactor`
- **格式**：`<类型>(<范围>): <简述>`
- **示例**：
  ```
  docs: 新增项目标准文档
  chore: 初始化项目结构
  feat: 实现金额转大写核心逻辑
  test: 补充单元测试
  ui: 搭建主界面
  fix: 修复 0 元边界
  ```
- **时机**：每阶段通过验收后**立即 commit**，一次完整 stage 一个 commit（或拆 2~3 个有意义的 commit）
- **范围**：禁止把未通过验收的探索性代码 commit
